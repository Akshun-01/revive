Revive API Contract

REST contract for the Revive revenue-recovery agent. Build the Next.js investigation workspace against these shapes - mock the planned endpoints until the backend lands them. Field names and enum values match the backend's Pydantic models exactly.

Base URL (dev)
http://127.0.0.1:8000
API prefix
/api/v1
MCP endpoint
/mcp
Content type
application/json
Live - implemented now Planned - none remaining; all endpoints below are live
CORS enabled (all origins, hackathon) and auth is a stub: send an X-User-Id header on every call (defaults to demo-user). Connections, investigations, approvals, SSE streaming and the MCP server are all live. POST /investigations runs synchronously and returns the full result; for a live timeline use the SSE /stream endpoint.

Reference

GET/api/v1/healthLive

Liveness plus current data source and LLM provider. Informational - the UI does not branch on it.

{ "status": "ok", "data_source": "seed", "llm_provider": "huggingface" }

data_source: seed (deterministic fixtures) or live (real Stripe / HubSpot / Slack).

GET/api/v1/connectionsLive

The user connects their own Stripe / HubSpot / Slack by pasting a token. Tokens are encrypted at rest and never returned to the browser. Send X-User-Id on every call. Build the Integrations / Connect screen against these three endpoints.

GET - list (no secrets)

[
  {
    "id": "1169c77ed5cc4558b61579294a9cd577",
    "provider": "hubspot",
    "status": "connected",
    "scopes": ["crm.read"],
    "created_at": "2026-09-13T18:15:39Z",
    "updated_at": "2026-09-13T18:15:39Z"
  }
]

POST - connect (provider: stripe | hubspot | slack)

{
  "provider": "hubspot",
  "credentials": { "token": "pat-na1-..." },
  "scopes": ["crm.read"]
}

Response 201 is the public Connection above - the token is not echoed. Idempotent per provider (re-posting updates in place). DELETE /api/v1/connections/{provider} returns 204, or 404 if not connected.

POST/api/v1/investigationsLive

Start an investigation. Runs synchronously and returns the full investigation object (same shape as GET below). If it pauses for sign-off, the response has status: "waiting_for_approval" and a pending_action.

Request

{ "customer": "Northwind Robotics" }

Response · 200 = the full investigation object (see GET below)

Seed-mode demo customers: Northwind Robotics, Cascade Freight, Meridian Analytics, Tidewater Systems, Solstice Media. GET /api/v1/investigations lists summaries.

GET/api/v1/investigations/streamLive

Server-Sent Events (text/event-stream) for the live timeline. This endpoint starts an investigation and streams progress: ?customer=<name>&user_id=<id> (query params - EventSource cannot set headers). Ends with investigation_completed, or approval_required if it pauses. Resume + stream the rest with GET /api/v1/investigations/{id}/resume-stream?approved=true.

POST/api/v1/approvals/{id}/approveLive

Approve - optionally editing parameters first. Resumes the workflow, which executes then verifies.

Request (body optional)

{ "edited_parameters": { "body": "Hi John, revised copy..." } }

Response

{ "id": "apr_1", "status": "approved" }
POST/api/v1/approvals/{id}/rejectLive

Reject the action. The investigation ends with status rejected.

Request

{ "reason": "Not ready for outreach." }

Response

{ "id": "apr_1", "status": "rejected" }

The evidence chain is the hero. Every diagnosis and recoverability references *_evidence_ids that map back to an evidence[].id. Render those as live links between the cause and its supporting evidence - that traceability is the product's core value.

Revive MCP server (/mcp)

For AI clients (Claude / ChatGPT / Cursor). Streamable-HTTP MCP mounted at /mcp. Curated business tools only - internal endpoints are not exposed. Same application services as REST, so behavior is identical across transports.

investigate_customer(customer)                       -> full investigation
get_investigation_result(investigation_id)           -> full investigation
list_recent_investigations()                         -> summaries
resume_recovery(investigation_id, approved, edits?)  -> resume a paused investigation

Integration notes

  • CORS - enabled for all origins (hackathon). Browser calls work.
  • Auth - stub: send X-User-Id on every call (defaults to demo-user).
  • Typed client - generate types from http://127.0.0.1:8000/openapi.json; interactive docs at /docs and /redoc.
  • Seed mode is deterministic - same input, same output. Build and demo the whole UI with no live credentials.
  • Sync model - POST /investigations returns the full result; if it pauses, poll GET /{id} or use audit[] for the timeline (SSE not built).
